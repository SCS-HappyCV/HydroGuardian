# HydroGuardian 人工智能创新比赛前端实施方案

## 1. 方案目标

本轮改造不以增加页面数量为目标，而是将现有“通用风险管理后台”重构为一套能够在 3—5 分钟内完整讲清项目创新性的比赛展示系统。

前端必须让评委直观看懂以下五件事：

1. 用户可以用自然语言描述水利巡查目标。
2. 系统会把任务编译为可执行的空间分析程序。
3. AI 会融合正射影像、点云和前后时相影像形成证据。
4. 系统输出的是可解释、可排序、可复核的风险对象，而不是单一识别框或热力图。
5. 风险结果可以继续生成处置建议和工单，形成业务闭环。

比赛版统一价值主张：

> HydroGuardian 水利智巡——自然语言驱动的多智能体水利隐患发现与闭环处置系统。

核心演示链路：

```text
自然语言巡查任务
→ 任务理解与空间程序编译
→ 正射影像、点云、前后时相数据融合
→ 候选区域与 EvidencePack 证据生成
→ 风险分级、排序与不确定性判断
→ 处置建议、工单与人工复核
```

## 2. 改造原则

### 2.1 比赛叙事优先

页面首先服务于评委理解，其次才服务于工程调试。`Mock/API`、`Scene ID`、`File ID`、原始 trace 等内容保留，但默认收进“高级设置”或“技术详情”抽屉。

### 2.2 一屏一个结论

每个核心页面只承担一个主要表达任务：

| 页面 | 评委看完应得到的结论 |
| --- | --- |
| 首页 | 这是一个自然语言驱动、多模态、可解释、能闭环的水利 AI 系统 |
| 态势总览 | 系统正在持续发现、研判和处置真实水利隐患 |
| 智巡任务 | 普通巡查需求可以直接转换为 AI 可执行任务 |
| 智能执行 | 多个智能体与算法服务正在协同完成证据推理 |
| 风险研判 | 每个风险都有位置、影像、点云、变化和置信依据 |
| 处置闭环 | AI 结果能够进入工单、复核和结果沉淀 |

### 2.3 业务语言优先

默认界面使用“场景数据”“AI 解析结果”“空间约束”“候选区域”“证据可信度”等业务语言。`ProgramBundle`、`EvidencePack` 等术语可作为技术标签或悬浮解释，不作为普通用户必须理解的主标题。

### 2.4 真实能力优先

所有演示文案和示例数据必须围绕当前后端真实能力组织：

- 正射影像；
- 点云及高程、坡度、几何特征；
- 前后时相变化检测；
- 自然语言任务解析；
- 空间 program 执行；
- 风险卡、建议卡和工单卡；
- `review_required`、低置信度和主动弃权。

不再把当前算法无法直接支持的实时水位曲线、设备联动延迟等内容作为主要演示案例。

## 3. 信息架构调整

### 3.1 统一品牌

全站统一使用：

- 中文名：`水利智巡`；
- 英文品牌：`HydroGuardian`；
- 完整名称：`HydroGuardian 水利智巡`；
- 副标题：`多智能体水利隐患发现与闭环处置系统`。

移除或替换“水域卫士”“风险哨兵系统”“智能水体风险监测平台”等并行名称。

### 3.2 主导航收敛

比赛模式主导航建议调整为：

1. 智巡总览
2. 发起巡查
3. 智能执行
4. 风险研判
5. 处置闭环
6. 案例复盘

知识库、规则编辑、模板管理、系统健康、权限和设置归入“系统管理”，默认折叠，避免分散评委注意力。

### 3.3 增加比赛模式

新增前端展示模式：

```text
VITE_PRESENTATION_MODE=competition | operations
```

- `competition`：默认隐藏开发字段，强化讲解引导和关键动画；
- `operations`：保留完整筛选、管理和联调能力。

该模式只控制信息密度和导航，不改变底层 API 调用。

## 4. 核心页面实施设计

## 4.1 首页：从功能入口改为创新成果封面

### 当前问题

- “7 个模块、无限规则、100% 闭环”缺乏可信度和技术指向；
- 六张功能卡像通用 SaaS 产品导航；
- 没有呈现影像、点云、智能体或空间证据。

### 改造布局

首屏采用左右分栏：

- 左侧：项目名称、价值主张、核心任务示例和“开始演示”按钮；
- 右侧：水利正射影像场景作为主视觉，叠加风险框、点云粒子、高程线和扫描动画；
- 中下方：以一条可视化流水线展示“任务 → 多模态证据 → 风险 → 工单”；
- 底部：展示四项真实能力，不使用夸张统计值。

建议能力指标：

- `3 类空间证据`：影像、点云、几何；
- `5 个协作智能体`：任务、证据、风险、建议、闭环；
- `全过程可追溯`：program、证据、风险、工单；
- `支持主动弃权`：低置信结果进入人工复核。

首页主按钮直接进入预置比赛案例，次按钮进入自由任务创建。

### 视觉实现

- 使用真实或经过脱敏的水利正射影像作为主背景；
- 叠加 SVG 风险多边形、测距线、点云粒子与轻量扫描光带；
- 动画控制在 200—600ms，避免大面积持续闪烁；
- 首屏避免出现表格和复杂表单。

## 4.2 智巡总览：从统计后台改为水利 AI 驾驶舱

### 页面目标

让评委在 10 秒内看到“发现了什么、证据是否可靠、哪些需要处置”。

### 建议布局

第一行：四个关键成果卡。

- 今日完成智巡任务；
- 发现候选风险区域；
- 高优先级风险；
- 已形成处置闭环。

第二行：场景主图占据约 2/3 宽度，右侧展示 AI 研判摘要。

- 正射影像风险分布；
- 风险类型和等级图例；
- 当前最高风险及核心证据；
- “进入风险研判”快捷入口。

第三行：展示 AI 闭环漏斗。

```text
已解析任务 → 已生成证据 → 已确认风险 → 已创建工单 → 已完成复核
```

将“失败任务”等工程指标降为次要状态，避免成为主视觉。

## 4.3 发起巡查：突出自然语言到空间任务的转换

### 页面目标

让评委看到自然语言不是普通聊天输入，而是会被编译成结构化、可执行的空间任务。

### 默认比赛界面

页面分为三步：

1. 描述巡查目标；
2. 选择或上传场景数据；
3. 确认 AI 解析结果并执行。

自然语言示例统一为后端真实支持的任务：

- 找出靠近水线的细长沟渠，并排除道路；
- 找出高于水线的陡坡裸地区域；
- 筛查近水扰动区域，并按风险高低排序。

右侧“AI 解析结果”不再只展示模板、区域和优先级，而应展示：

- 目标对象；
- 空间关系；
- 几何约束；
- 排除条件；
- 排序规则；
- 所需证据模态。

示例：

```text
目标：细长沟渠
空间关系：距水线 ≤ 30m
几何约束：高长宽比、连续区域
排除对象：道路
证据来源：正射影像 + 点云 + 几何特征
输出：候选区域，按综合风险降序
```

### 高级设置

以下内容默认折叠：

- Mock/API/Hybrid 模式；
- Scene ID；
- File ID；
- 预处理参数；
- 接口诊断信息。

比赛默认只显示“使用比赛样例”“上传本地场景”“使用已有场景”三种业务选项。

## 4.4 智能执行：从日志监控改为多智能体协作舞台

### 页面目标

把后端 LangGraph 主链路转化为清晰、动态、可解释的 AI 协作过程。

### 主视觉

用横向流程或节点网络展示八个真实阶段：

1. 理解巡查任务；
2. 编译空间程序；
3. 准备场景样本；
4. 执行三维证据检索；
5. 检测前后变化；
6. 评估风险；
7. 生成处置建议；
8. 创建闭环工单。

每个节点显示：

- 当前状态；
- 耗时；
- 一句业务结果；
- 使用的数据或工具。

示例节点结果：

```text
任务理解完成
识别目标：近水细长沟渠
解析约束：近水、细长、排除道路
耗时：0.8s
```

### 辅助区域

- 左侧或底部展示输入场景缩略图；
- 右侧实时累积“已获得的证据”；
- 原始 trace 和错误日志放入“技术详情”；
- 完成后以明显的结果摘要承接到风险研判页面。

## 4.5 风险研判：作为全站视觉与创新中心

### 页面目标

证明系统不仅识别了区域，而且能解释“为什么是风险、证据是否可靠、下一步该做什么”。

### 推荐三栏布局

- 左栏：风险候选列表和排序；
- 中栏：大幅场景证据画布；
- 右栏：证据链、风险解释和处置建议。

### 中央证据画布

支持四种视图切换：

1. 正射影像；
2. 点云/高程；
3. 前后影像对比；
4. 变化掩膜。

保持相同候选区域在不同视图中的联动高亮。中央画布应占页面最大面积，风险框、区域轮廓和空间距离标注需要清晰可见。

### 右侧解释面板

将现有零散指标组织为“风险判断依据”：

- 风险类型和等级；
- 综合置信度；
- 影像证据；
- 点云/几何证据；
- 时相变化证据；
- 规则或空间约束命中情况；
- 不确定性与是否需要人工复核；
- AI 处置建议。

`弃权概率`建议改名为“模型不确定性”，并用一句解释说明主动弃权是系统安全能力，而不是算法失败。

### 结果动作

主操作保持两项：

- 生成处置工单；
- 标记人工复核。

弱化其他按钮，保证演示路径清晰。

## 4.6 处置闭环：突出 AI 到业务价值的最后一公里

### 页面目标

让评委看到风险结果能够真正被采用，而不是停留在算法展示。

### 工单详情新增内容

- 来源任务；
- 风险区域缩略图；
- AI 判断摘要；
- 核心证据；
- AI 建议的处置动作；
- 人工复核意见；
- 完整状态时间线。

状态流建议展示为：

```text
AI 发现 → 人工确认 → 派发处置 → 现场反馈 → 复核关闭
```

演示案例应预置一条已完成闭环的数据，用于证明系统结果可追溯。

## 5. 视觉系统实施规范

### 5.1 视觉主题

定位为“水利遥感数字孪生驾驶舱”，而不是普通深色后台。

- 主背景：深海军蓝 `#07111F`；
- 主品牌色：水利蓝 `#2F80ED`；
- 证据强调色：青色 `#2DD4BF`；
- 高风险：珊瑚红 `#FF5D5D`；
- 中风险：琥珀黄 `#F5B942`；
- 安全/完成：生态绿 `#39C98A`；
- 点云/空间计算：紫蓝 `#8B7CFF`。

### 5.2 页面层级

- 一级数字：28—36px；
- 页面标题：28—32px；
- 核心结论：18—22px；
- 正文：14—16px；
- 技术辅助信息：12px；
- 一屏卡片数量控制在 4—7 个；
- 关键地图或证据画布面积不少于内容区的 45%。

### 5.3 动效规范

保留有解释价值的动效：

- 智能体节点依次激活；
- 场景扫描线；
- 风险区域逐个出现；
- 证据连线汇聚到风险结论；
- 工单闭环状态推进。

避免：

- 大面积无限脉冲；
- 无业务意义的悬浮和旋转；
- 多处同时闪烁；
- 超过 800ms 的页面进入动画。

### 5.4 图表与地图

- 不使用空白占位地图作为比赛默认内容；
- 所有统计图必须能够点击联动到风险对象；
- 风险颜色全站一致；
- 同一候选区域在地图、列表、证据面板中使用同一编号；
- 图表标题写业务结论，避免只写“分布”“趋势”。

## 6. 演示数据与比赛脚本

### 6.1 建立唯一黄金案例

建议选择“近水扰动与疑似沟渠筛查”作为默认案例，准备完整资产：

- 一张正射影像；
- 对应点云或点云投影图；
- 前后时相影像；
- 变化掩膜；
- 3—5 个候选区域；
- 至少一个高风险、一个中风险、一个待复核对象；
- 一条完整工单闭环记录。

所有页面默认围绕同一个 `taskId / caseId / sceneId` 展示，避免页面之间数据故事断裂。

### 6.2 演示路径

推荐现场操作控制在 3—5 分钟：

1. 首页用 20 秒说明项目价值；
2. 点击预置案例进入发起巡查；
3. 展示自然语言被拆解为空间约束；
4. 启动任务并观看多智能体节点执行；
5. 进入风险研判，切换影像、点云和变化视图；
6. 打开高风险对象解释证据；
7. 对待复核对象展示主动弃权；
8. 生成工单并展示完整闭环。

### 6.3 演示兜底

- 保留 `hybrid` 数据模式；
- 比赛模式下不显示“API 失败后回退 Mock”等技术提示，改为“已切换至离线演示数据”；
- 黄金案例的所有图像和结构化快照应本地可用；
- 后端不可用时仍能完整走完相同页面路径；
- 在线和离线结果的数据结构保持一致。

## 8. 分阶段实施计划

## P0：品牌与演示数据统一（0.5—1 天）

任务：

- 统一全站品牌与项目副标题；
- 清理与算法能力不一致的示例文案；
- 确定唯一黄金案例；
- 对齐任务、风险、工单、影像资产之间的 ID；
- 修正基础语言和页面元信息。

验收：

- 全站不再出现三个产品名并存；
- 任意核心页面都围绕同一个水利巡查主题；
- 黄金案例可以从任务一路追踪到工单。

## P1：首页与导航比赛化（1—2 天）

任务：

- 重构首页 Hero 和多模态主视觉；
- 增加 AI 闭环流程带；
- 收敛主导航；
- 增加比赛模式；
- 调整全局色彩、背景、卡片和排版层级。

验收：

- 评委在首屏 10 秒内能说出项目的输入、AI 能力和输出；
- 首页没有空泛统计和通用 SaaS 功能宫格；
- 1280×720 投影环境下首屏信息完整。

## P2：任务与智能执行可视化（2—3 天）

任务：

- 将任务创建重构为三步式流程；
- 新增自然语言意图编译预览；
- 将开发字段折叠进高级设置；
- 新增多智能体执行图和实时证据流；
- 将原始日志降为技术详情。

验收：

- 三个标准任务均能显示正确的目标、约束、排除项和证据模态；
- API trace 能映射到八个业务阶段；
- Mock 和 API 模式使用同一可视化结构。

## P3：风险证据中心重构（3—4 天）

任务：

- 将风险工作区重构为三栏证据研判布局；
- 整合正射影像、点云、前后对比和变化掩膜；
- 建立候选区域跨视图联动；
- 重写风险解释和不确定性表达；
- 把 AI 建议接入风险详情。

验收：

- 选中任一风险时，列表、场景、证据和建议同步变化；
- 每个风险至少显示两类有效证据；
- 待复核对象清楚说明“不确定在哪里”；
- 无真实可视化资产时提供一致且美观的离线兜底。

## P4：闭环、动效与比赛彩排（1—2 天）

任务：

- 增加工单 AI 来源摘要和闭环时间线；
- 完善关键过渡动效；
- 准备一键重置黄金案例；
- 进行 1280×720、1440×900 和 1920×1080 检查；
- 完成无后端、慢网络和接口失败演练；
- 按 3—5 分钟比赛脚本彩排。

验收：

- 主演示路径无死链、空状态或开发报错；
- 离线状态可以完整演示；
- 关键文字在投影环境下清晰可读；
- 从首页到闭环结束不超过 8 次主要点击。

## 9. 优先级与工期

| 优先级 | 内容 | 预估工作量 | 比赛价值 |
| --- | --- | ---: | --- |
| P0 | 品牌、案例和数据统一 | 0.5—1 天 | 消除项目叙事冲突 |
| P1 | 首页、导航、全局视觉 | 1—2 天 | 建立第一印象 |
| P2 | 任务编译与多智能体执行 | 2—3 天 | 直接展示 AI 创新 |
| P3 | 多模态风险证据中心 | 3—4 天 | 形成核心技术亮点 |
| P4 | 闭环、兜底和演示彩排 | 1—2 天 | 保证比赛现场稳定 |

完整实施约需 8—12 个开发日。若时间有限，至少完成 P0—P3 的首页、任务编译、智能执行图和风险证据画布。

## 10. 总体验收标准

### 10.1 内容验收

- 品牌、项目定位和术语全站一致；
- 示例任务与实际算法能力一致；
- 清楚展示自然语言编译、三模态证据、多智能体协作和主动弃权；
- 每个风险都有证据、解释、建议和后续动作；
- 主路径能够形成任务到工单的完整闭环。

### 10.2 视觉验收

- 首屏具有明确水利遥感场景特征；
- 核心页面不存在大面积空白占位；
- 地图/证据画布是风险页面视觉中心；
- 风险颜色和候选区域编号全站一致；
- 动效服务于任务执行和证据形成过程；
- 投影环境下主要信息无需缩放即可阅读。

### 10.3 工程验收

- `pnpm check` 通过；
- `pnpm build` 通过；
- 核心页面无控制台阻断错误；
- API、Hybrid 和离线演示模式均可进入完整链路；
- 页面刷新后能够恢复当前比赛案例；
- 关键图片全部具有本地兜底资源；
- 不修改或破坏现有后端 API 契约。

## 11. 推荐落地顺序

建议实际开发时严格按以下顺序推进：

```text
统一品牌与黄金案例
→ 建立比赛模式和全局视觉令牌
→ 重构首页
→ 重构任务意图编译
→ 重构多智能体执行页
→ 重构风险证据中心
→ 补齐工单 AI 来源
→ 联调、离线兜底和比赛彩排
```

这个顺序可以确保每完成一个阶段，系统的比赛表达能力都得到独立提升，同时避免先做局部视觉美化后再反复调整数据结构和页面叙事。
